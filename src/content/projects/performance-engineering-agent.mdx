## Problem

Performance analysis on real hardware was eating a large share of engineering time. The goal was to cut that manual work and still produce root-cause findings a performance engineer could trust.

The public result is 80% less manual analysis (30+ hrs/week).

## Approach

Performance engineering at Ampere, two ways: I built an agent that does root-cause analysis on real hardware (five CLI profilers over SSH through an async MCP server, with performance playbooks turned into executable skills), and I worked on and supported hands-on case studies across LLM inference, recommendation models and network regressions.

The public architecture is generic: agent and skill system to async MCP server to SSH to one runner machine driving several systems under test.

## Key decisions

Playbooks became executable skills, so the agent could run a known performance method instead of improvising each time.

Evaluation used LLM-as-a-Judge over a 200-sample golden dataset of multi-turn trajectories. Agreement with expert assessments was 88%, with Cohen's kappa 0.81.

## Results

The case studies below were worked on or supported using the agent alongside hands-on profiling with hardware counters, roofline reasoning and controlled experiments. Each is a method-plus-finding narrative. No figures. Trace replays of these stories, if shown, are illustrative.

### Llama token generation

The agent compared instruction counts and memory-stall behavior across implementations, ruled out a slow library as the cause, and pointed to kernel and prefetch changes that improved batched throughput.
